## 09:50 — Decision: Python 3.15 Linux `_decimal` fix — `builld_libmpdec` goes in the 3.15 version block, not base deps

**Context:** First Linux 3.15 builds failed with `The necessary bits to build
these optional modules were not found: _decimal`. CPython 3.15 removed the
vendored libmpdec (bundled fallback gone), so an external mpdecimal is now
mandatory. macOS hit the same thing and was already fixed (10/22) by calling
`builld_libmpdec` in the 3.15 Darwin block of `build_python_runtime`.

**Decision (applied by user, in working tree, uncommitted):** Added
`builld_libmpdec` to all three Linux cases of the 3.15 block
(debian13 / centos9 / amzn2023), after `build_openssl` and before
`build_sqlite3` — mirroring the macOS relative order. Call sites now:
`build_runtime.sh:1519,1527,1533,1539` (definition `:1082`).

Explicitly rejected the alternative of adding mpdecimal to
`build_linux_base_dependencies` / `build_debian_base_dependencies`:

- **Base deps don't build from source** — they harvest distro `-devel`
  packages (`yum --installroot` / Debian extract). mpdecimal there would be
  distro-versioned (unpinned), and likely not even packaged in AL2023 /
  CentOS 9 base repos. The `verv` 3.15 rows already pin mpdecimal `4.0.1` as
  field 14 — only the Linux call was missing, so source-build was the
  original intent.
- **Base deps are shared by every version block 3.7→3.15.** Since 3.13,
  CPython configure defaults to `--with-system-libmpdec=yes` with a vendored
  fallback — a system libmpdec in the shared deps root would silently flip
  3.13/3.14 `_decimal` from vendored-static to a shared distro lib. Same
  churn class as the 08-07 krb5 decision (declined: don't change stable
  version lines).
- **Precedent:** `build_libnsl` — the existing version-scoped source dep
  (≤3.12) — lives in the version blocks, never inside base deps.

**Mechanics (why no other change was needed):** Linux env blocks already
carry `-I/-L ${path_to_local}` + rpath; `PKG_CONFIG_PATH` is unset, so
configure's pkg-config probe falls back to `-lmpdec`, resolved via the
existing LDFLAGS. `libmpdec.so` links only libc/libm → no loadable-refs
allowlist entry needed; `fix_runtime_paths_linux` rewrites its rpath like
every other `local/` lib.
